# 추천 엔진

`DeterministicCandidateRanker` 버전 `deterministic-v2`는 정규화된 Provider 후보의 점수를 백엔드 TypeScript에서 계산한다. 검증된 취향과 선택적인 지역 혼잡도 관측값 하나를 입력받으며 LLM은 호출하지 않는다.

## 가중치

| 항목 | 기본값 |
| --- | ---: |
| preference | 0.35 |
| crowd | 0.20 |
| distance | 0.15 |
| time | 0.15 |
| budget | 0.10 |
| diversity | 0.05 |
| area | 0.00 |

동적 규칙은 `crowded`, `very_crowded` 또는 조용한 장소 선호가 있을 때 crowd 가중치를 높이고, 지역을 알 수 있을 때 area 가중치를 추가한다. 모든 음이 아닌 값을 합계가 1이 되도록 정규화한다. 적용한 가중치는 `RecommendationResult.finalWeights`에 저장하고 `trip.appliedWeights`로 반환한다.

## 항목별 점수

- `preference`: 확인된 관심사·카테고리 Alias와 일치하면 `1.0`, 일치하지 않으면 `0.2`, 신호를 사용할 수 없으면 중립값 `0.5`다.
- `crowd`: 지역 단위 혼잡도 문구를 한산함 `1.0`, 보통·약간 붐빔 `0.65`, 붐빔 `0.15`, 알 수 없음 `0.5`로 변환한다.
- `distance`: 좌표가 있는 모든 후보의 지리적 중심으로부터 거리를 `1 / (1 + km / 1.5)`로 계산한다. 위치나 중심을 알 수 없으면 `0.5`다.
- `time`: Provider가 제공한 영업시간이 요청한 체류 시간을 포함하면 `1.0`, 일부만 겹치면 `0.4`, 전혀 겹치지 않으면 `0`, 영업시간을 알 수 없으면 `0.5`다.
- `budget`: Provider 또는 설정에서 가져온 후보 비용과 전체 예산을 비교한다. 비용이나 예산이 없으면 `0.5`, 예산을 초과하면 `0`, 감당 가능한 확인된 비용은 `0.5`에서 `1.0` 사이로 조정한다.
- `diversity`: 후보 중 적게 등장하는 카테고리에 더 높은 점수를 준다. 카테고리가 없으면 `0.5`다.
- `area`: 정규화된 지역이 주소에 포함되면 `1.0`, 그렇지 않으면 `0.2`, 지역이 없으면 `0.5`다.

가중 합계와 항목별 점수는 반올림하고 `[0,1]` 범위로 제한한다. 동점은 Provider/Source 식별자를 사용해 안정적으로 정렬한다.

## 알 수 없는 데이터

Ranker는 선택적인 비용과 영업시간 Field를 받지만, 현재 NAVER Local Search Normalizer는 이를 제공하지 않는다. 따라서 Live 및 Mock 장소 후보는 일반적으로 중립적인 time/budget 값과 명시적인 경고를 받는다. 이는 알 수 없는 데이터에 대한 정책 점수일 뿐, 장소가 영업 중이거나 예산에 맞는다는 주장이 아니다.

지역 혼잡도는 특정 장소 내부 혼잡도가 아니다. 추천 이유와 경고에서 이 범위를 반복해서 알린다. 검증된 좌표가 없는 장소 후보는 순위·경로 생성 전에 `TripsService`에서 제외하고, 제외 개수를 경고에 표시한다.

## 설명과 감사 추적

순위가 계산된 모든 후보에는 일본어로 된 결정론적 `reason`과 전체 `scoreBreakdown`이 있다. 백엔드는 Algorithm 버전, 적용한 가중치, 후보 수, 각 후보의 항목별 점수를 저장한다. 선택된 경유지는 추천 이유와 점수 Snapshot을 복사하므로 프런트엔드가 순위를 다시 계산하지 않고도 `なぜここがおすすめ？`를 표시할 수 있다.
